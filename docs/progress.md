## Этап 1 — Node.js изнутри

В `labs/node-core/` присутствуют:
- HTTP-сервер на `node:http`, ручная обработка query и JSON-тела, лимит размера запросов, `requests.http`.
- Упражнения с файловыми потоками, копированием, `pipeline` и backpressure.
- Упражнения с CPU-bound обработкой и Worker Threads (`cpu-worker.cjs`, `worker-demo.cjs`, другие файлы).

**Не утверждаем без проверок**, что все лаборатории и граничные случаи пройдены. Event loop, graceful shutdown и детальная проверка поточных ошибок остаются темами для повторения. Основной путь обучения продолжается в NestJS, не блокируется лабораториями.

## Этап 2 — HTTP / NestJS: реализовано

### Практика 2.1. Модуль мероприятий
- [x] Созданы `EventsModule`, `EventsController`, `EventsService`.
- [x] `EventsModule` подключён в `AppModule`; контроллер получает сервис через Dependency Injection.

### Практика 2.2. Фильтрация
- [x] Query-параметры `city` и `category` необязательные.
- [x] Фильтрация без учёта регистра, фильтры применяются совместно.
- [x] Фильтруется выборка в сервисе, а не исходный массив; `total` считается после фильтрации.

### Практика 2.3. Пагинация
- [x] `page` и `limit`, значения по умолчанию 1 и 10.
- [x] Сначала фильтрация, затем `offset` и `slice`.
- [x] Возвращаются `items`, `total`, `page`, `limit`, `totalPages`.
- [x] Для `totalPages` используется `Math.ceil`.

### Практика 2.4. DTO и ValidationPipe
- [x] `GetEventsQueryDto` с `IsOptional`, `IsString`, `Type(() => Number)`, `IsInt`, `Min`, `Max`.
- [x] Контроллер принимает единый DTO через `@Query()`.
- [x] В `main.ts` зарегистрирован глобальный `ValidationPipe` с `transform: true`, `whitelist: true`, `forbidNonWhitelisted: true`.
- [x] Ручная проверка диапазона `page/limit` удалена из `EventsService`.
- [x] В `apps/api/requests/events.http` сохранены запросы для ручной проверки фильтрации, пагинации, ошибок и неизвестного параметра.

### Что поняли на занятиях
- Роли Module / Controller / Provider (Service), DI.
- Query string передаёт строковые значения; TypeScript-тип сам по себе не валидирует HTTP-ввод.
- Query-параметры, совмещённые фильтры, offset pagination, различие `total` и размера страницы.
- `DefaultValuePipe` должен выполняться раньше `ParseIntPipe`, если параметр необязателен.
- DTO-класс и runtime-декораторы; `class-transformer` преобразует значения, `class-validator` проверяет их.
- Без `@Type(() => Number)` строка `page=5` в нашем DTO не пройдёт `@IsInt()` при текущих настройках без неявной конверсии.

## Технический долг, обнаруженный при проверке GitHub

**Приоритет: перед следующей практикой.**

1. **Зависимости установлены не в тот workspace.** В корневом `package.json` появились `class-transformer` и `class-validator` и закоммичен `package-lock.json` (npm). При этом `apps/api/package.json` не содержит эти зависимости, а корневой importer `.` в `pnpm-lock.yaml` пуст. Нужно привести зависимости к одному менеджеру `pnpm`: добавить библиотеки непосредственно в `apps/api`, обновить `pnpm-lock.yaml`, удалить лишние npm root-зависимости и `package-lock.json`, проверить чистую установку. **Пока не исправлено.**
2. В DTO у `@Max(50)` ошибочный текст: «Лимит должен быть больше 50» вместо «не больше 50».
3. Остались неиспользуемые импорты в контроллере и сервисе; в сервисе осталось поле `maxLimit`, которое больше не используется.
4. `apps/api/tsconfig.build.tsbuildinfo` отслеживается Git. Добавить `*.tsbuildinfo` в `.gitignore` и убрать файл из индекса без удаления локального экземпляра.
5. Тесты `app.controller.spec.ts` и `test/app.e2e-spec.ts` содержат старые заготовки и не соответствуют полностью текущему приложению.
6. Проверка полной матрицы `events.http`, `pnpm --filter api build`, `lint`, `test`, `test:e2e` на актуальной версии не подтверждена.

## Правила обучения и учёта прогресса

- Сначала теория: проблема → внутренний механизм → альтернативы. Потом самостоятельное ТЗ и команды проверки.
- Не писать готовую реализацию за разработчика, пока он сам её не запросит; сначала давать небольшие подсказки.
- Не зацикливаться на косметике; приоритет — Backend, PostgreSQL, безопасность, конкурентность, тесты.
- Код в Git ≠ прошедшие тесты. Явно отделяем подтверждённую работу от предположений и незавершённых проверок.
