## Этап 1 — Node.js изнутри (текущий)

### Уже написано

Файл: `labs/node-core/http-server.cjs`.

- [x] HTTP-сервер на встроенном `node:http` без фреймворка (CommonJS).
- [x] `GET /health` → JSON с `status: ok`.
- [x] `GET /hello?name=...&age=...` → разбор URL и query-параметров; ошибка `400` при отсутствии имени.
- [x] `POST /echo` → ручное чтение входного потока через события `data`/`end`, сборка `Buffer` и `JSON.parse`.
- [x] Обработка пустого тела (`400`) и некорректного JSON (`400`).
- [x] Контроль размера тела в байтах: лимит **1 МиБ**, при превышении — `413`.
- [x] Обработка ошибки потока запроса и fallback `404` для неизвестного маршрута.
- [x] Подготовлен `labs/node-core/requests.http` со сценариями обычного, пустого, невалидного, слишком большого и ровно граничного тела запроса; добавлены тестовые JSON-файлы.

### Ещё не закрыто

- [ ] Выполнить и зафиксировать результаты HTTP-сценариев (наличие `requests.http` само по себе не доказывает их прохождение).
- [ ] Разобрать краевые случаи HTTP-запросов: обрыв соединения, потоковые ошибки, корректное завершение ответа.
- [ ] Практика event loop: timers, microtasks, `process.nextTick`, порядок выполнения.
- [ ] I/O, `Buffer`, файловые streams и backpressure; сравнить потоковое чтение и чтение файла целиком.
- [ ] CPU-bound обработчик: измерить блокировку event loop и попробовать Worker Threads.
- [ ] Реализовать graceful shutdown (`SIGINT`/`SIGTERM`) для учебного HTTP-сервера.
- [ ] Мини-собеседование и объяснение самостоятельно: event loop, потоки, ошибки, Worker Threads vs I/O.
